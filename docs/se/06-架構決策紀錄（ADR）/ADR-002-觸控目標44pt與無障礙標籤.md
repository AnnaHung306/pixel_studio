# ADR-002：觸控裝置一律 44pt 觸控目標；按鈕都有無障礙名稱
- 狀態：採納（1.1.0）
- 背景：NFR-4 要求觸控目標 ≥ 44pt（Apple HIG）。1.0.0 的頂端列按鈕 36px、工具 38px、時間軸圖層的顯示／鎖定按鈕只有 24px、影格格子 36×30，iPad 上手指與 Apple Pencil 容易點錯；圖示按鈕（↶ ☰ 👁 ⏮）只有符號，VoiceOver 念不出用途。
- 決定：
  1. 啟動時對 iOS／iPadOS（UA 判斷）或主要指標為 coarse 的裝置加 `html.touch`；所有尺寸放大集中在 CSS `html.touch …` 區塊，桌面維持緊湊版面。
  2. 觸控版：按鈕、工具、選單項目、分頁、輸入框、下拉選單、時間軸影格／cel／圖層按鈕 ≥ 44×44 CSS px；時間軸格寬 `CW` 與圖層欄寬 `LH_W` 隨之放大（JS 與 CSS 同步）。
  3. 例外（密集網格，業界慣例）：調色盤色塊 ≥ 30pt、主／次色塊 30pt（兩者重疊呈現）、標籤條、核取方塊／滑桿本體（以整個 label 為點擊區）。
  4. 窄手機（≤ 430px）頂端列放不下 8 個 44pt 按鈕：格線開關移到「☰ → 檢視」。
  5. `h()` 建立 `<button>` 時，若只有符號而有 `title`，自動以 title（去掉快捷鍵括號）設 `aria-label`；靜態按鈕在啟動時補上；工具按鈕帶 `aria-pressed`；對話框 `role=dialog`、`aria-modal`。
  6. e2e 新增 `a11y` 測試組：觸控設定逐一量測主畫面、各底部面板、主選單與 3 個對話框的所有可點元素；所有設定檢查按鈕都有可讀名稱。
- 後果：iPad 畫布可用面積略減（工具列 +6px、選項列 +12px、時間軸 +26px）；手機時間軸控制列會換成多行（列為階段 D 介面重設計的輸入）。e2e 的 safe-area 模擬改為依方向的真實 iOS 數值（直向上／下、橫向左／右／下），原本四邊同時 44px 的模擬在實機不可能發生。

# v1.1.0 版本報告

- 日期：2026-10-27　迭代：2　類型：優化／新功能（次版號）
- 主題：iPad 觸控目標 ≥ 44pt、VoiceOver 無障礙名稱（ADR-002）

## 改了什麼
- **新增**：觸控裝置（iPadOS／iOS 或 coarse 指標）自動套用 `html.touch`：頂端列、工具、選項列、選單、對話框按鈕、輸入框、時間軸影格／cel／圖層顯示與鎖定按鈕、歷史項目一律 ≥ 44×44pt；圖示按鈕自動帶 `aria-label`（VoiceOver 念「復原」而非「↶」）、工具按鈕 `aria-pressed`、對話框 `role=dialog`、畫布與工具列語意標籤、調色盤色塊與錨點按鈕名稱；「☰ → 檢視」新增像素格線開關（窄手機頂端列放不下時使用）；e2e `a11y` 測試組：量測主畫面、底部面板、主選單與 3 個對話框所有可點元素的大小與名稱
- **變更**：窄手機（≤ 430px）頂端列隱藏格線鈕；時間軸格寬與圖層欄寬在觸控裝置放大；e2e safe-area 模擬改為依方向的真實 iOS 數值；側邊面板開啟改為等待轉場完成（原固定等待在高負載時偶發失敗）；時間軸捲動區加上 scroll-padding（上方影格列、左側圖層欄為 sticky），捲動到某圖層或影格時不會被標題列蓋住；e2e `boot` 改為等待標題渲染（高負載下標題在下一個動畫影格才更新，原固定等待偶發失敗）

## 為什麼
NFR-4 要求 44pt 觸控目標；1.0 的按鈕 24–38px 在 iPad 上手指與 Apple Pencil 容易點錯，是 iPad 體驗最大的落差（優先序：iPad 體驗僅次於 bug）。VoiceOver 只念符號也違反無障礙需求。

## iPad 影響
所有 iPad 機型的按鈕變大、時間軸格子 44pt，點選更準；代價是畫布區域少約 6px（寬）／38px（高），將在後續「可收合面板」改善。桌面版維持緊湊尺寸。

## 已知問題
手機直向時間軸控制列會換成 3–4 行，佔用底部面板空間（列入階段 D 介面重設計）；調色盤色塊為 30pt（密集網格例外，見 ADR-002）。

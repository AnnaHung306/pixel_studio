# v1.0.1 版本報告

- 日期：2026-10-26　迭代：1　類型：修正（修訂號）
- 主題：修正寫死的版本號（關於、/api/health、MCP、OpenAPI、精靈圖 JSON）；版本單一來源；平行 e2e

## 改了什麼
- **修正**：「關於 Pixel Studio」顯示寫死的「0.1」，`/api/health`、MCP `serverInfo`、OpenAPI `info.version`、精靈圖 JSON `meta.version` 寫死「0.1.0」——全部改為實際版本；e2e 測試穩定性：平行執行時多個設定共用伺服器造成專案名稱衝突、參考圖面板重繪時輸入到已移除的欄位、底部面板轉場以固定等待（改為等待轉場完成）
- **變更**：版本單一來源為 package.json：伺服器 `server/version.js`、前端由建置產生 `public/js/version.js`；Service Worker 快取名改為 `pixel-studio-<版本>-<內容雜湊>`，可從快取名辨識離線版本
- **新增**：`npm run e2e:par`：全矩陣 e2e 分行程平行執行；迴歸測試：smoke 驗證 3 個伺服器版本欄位；e2e 驗證「關於」版本與離線快取名；發布輔助：`work/bump.py`（同步 package/package-lock 版本）、`work/release_docs.py`（依測試結果產生 CHANGELOG／進度表／QA／版本報告）

## 為什麼
1.0.0 起每版都要在 git 與 App 內留下版本號；原本 5 處寫死 0.1／0.1.0，使用者與 AI 用戶端看到的版本都錯，實機回報問題時也無法分辨版本。依規則先寫重現測試（smoke／e2e 在修正前失敗），再修正。
